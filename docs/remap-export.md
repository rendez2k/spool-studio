# Local 3MF remapping

In Match a print, select a library filament for each included slot (the same selection is used for NFC). Suggest close stock only fills unchosen slots with a same-material, same-known-finish candidate within the existing close-colour threshold or a named exact match. Explicit choices are retained. Review & download 3MF shows the replacements before generating a new `-my-filaments.3mf` file.

The original File object stays on the device. Export re-reads it, validates its ZIP layout and bounded JSON metadata, and rewrites only `Metadata/project_settings.config`. Compressed bytes and local records for every other archive entry are preserved, including object assignments, painted triangles, assemblies, transforms and saved thumbnails. Indices never change; duplicate spool choices do not merge slots. Excluded slots remain original, not removed from the model.

Replacement slots have the library swatch, vendor, shade and a clearly marked project-local preset name. Their source vendor IDs and inheritance links are cleared so they are not presented as the original manufacturer's named preset. Per-filament difference markers preserve edited vendor/name data. The full original thermal, flow, speed, purge and printer settings remain: inventory entries are not calibrated slicer profiles. Review/select actual profiles and printer, recalculate purging and re-slice in the target slicer. Thumbnails remain original images. This does not convert a Bambu printer configuration into a Snapmaker configuration or produce new G-code.

Supported inputs are normal unsliced Bambu/Orca project archives (stored/deflated entries), up to 100 MB, 64 slots and 2 MB settings. Export rejects encrypted, split, ZIP64, signed, pre-sliced, duplicate/path-ambiguous or overlapping archives; unsupported embedded filament preset bundles; incomplete parallel slot arrays; and virtual mixed-filament replacement slots. It also rejects material changes, uncounted/unavailable stock and invalid hex values. Unsupported input remains usable for comparison where the existing reader permits it; original files are never modified.

No 3MF data is uploaded, stored in the database or transferred in NFC queues. The file handle is released with the project on replacement/account changes. An export finishing after its account/project/choices change is discarded. There is no NFC four-slot restriction on 3MF export.

Tests cover stored and deflated ZIPs with data descriptors, settings CRC, byte-preservation of non-settings records, rereading with the matcher, unchanged calibration and excluded slots, unsafe inputs, multiple slots sharing stock, review/suggestion controls and stale account exports. These are not a substitute for opening the result in the user's target slicer before printing.

Format references checked 9 September 2026: [Orca 3MF implementation](https://github.com/OrcaSlicer/OrcaSlicer/blob/main/src/libslic3r/Format/bbs_3mf.cpp) and [preset bundle import](https://github.com/OrcaSlicer/OrcaSlicer/blob/main/src/libslic3r/PresetBundle.cpp). Keep this module independent of either site's account data and hosting binding when copying between editions.
